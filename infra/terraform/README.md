That message is the thing to act on. A new AWS account under verification
cannot reliably launch resources, so **`terraform apply` will fail against this
account until AWS finishes verifying it** — and it will fail partway, which is
worse than failing at the start. Read is fine; create is not.

## Bootstrap (once)

State is local until the account can make a bucket, because the bucket is
itself a resource this account cannot create yet.

```bash
aws s3api create-bucket \
  --bucket aajoo-terraform-state \
  --region ap-south-1 \
  --create-bucket-configuration LocationConstraint=ap-south-1
aws s3api put-bucket-versioning \
  --bucket aajoo-terraform-state --versioning-configuration Status=Enabled
aws s3api put-public-access-block --bucket aajoo-terraform-state \
  --public-access-block-configuration \
  "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"
```

Then uncomment the `backend "s3"` block in `versions.tf` and
`terraform init -migrate-state`.

## Running it

```bash
terraform init
terraform plan      # read this. It should create ~25 resources and destroy 0.
terraform apply
```

`terraform plan` is the review step, not a formality: the first apply creates a
**billable, durable** database. Read the plan output before typing yes.

## What this creates, and what it costs

| Resource | Notes |
|---|---|
| VPC, 2 public + 2 private subnets, IGW | **No NAT gateway** — see `network.tf` |
| 3 security groups | internet → ALB → tasks → RDS, each rule naming a group |
| 2 ECR repositories | immutable tags, scan on push, keep last 20 |
| RDS MySQL 8 `db.t4g.micro`, 20 GB gp3 | encrypted, private, 7-day backups, deletion protection ON |
| 4 SSM parameters | DB host, name, user, and the **password as SecureString** |

Roughly **$15–20/month** for the database and storage at this size. The ALB
(~$18–20) and Fargate arrive on Day 2.

**The master password is generated by Terraform and written straight to SSM.**
Nobody types it, nobody pastes it, and it never appears in a message. It does
land in `terraform.tfstate` — which is why state is gitignored here and why the
remote backend is encrypted.

## Deliberate choices worth not undoing

**No NAT gateway.** Fargate tasks sit in public subnets with public IPs and are
kept private by a security group that admits the ALB and nothing else. That
saves ~$32/month and puts the whole protection in one rule — which is why that
rule carries a comment rather than a line.

**Immutable image tags.** One tag means one artifact. Deployments reference a
commit SHA; a task definition pinned to `latest` cannot tell you what is
running.

**Deletion protection and a final snapshot.** Both default on. A `terraform
destroy` in the wrong directory should be annoying, not fatal.

**Two AZs, single-AZ database.** Two is RDS's floor for a subnet group, not a
resilience decision. The API runs at exactly one task (in-process rate limiter,
SEO cache, scheduler, Socket.io), so multi-AZ would double the instance cost to
buy a failover nothing can yet use.
